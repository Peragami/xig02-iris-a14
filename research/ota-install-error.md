# OTA（14.0.23.0 → 14.0.26.0）インストールエラーの解析

- 日時: 2026-11-18
- 方法: USBデバッグで再試行時の logcat を取得し、update_engine のログを解析（取得はユーザーのPCで OpenCode が実施。端末シリアル等の識別子はこの文書には含めない）
- 端末状態: 空き容量 28.1GB、Wi-Fi接続、充電中、時刻正常。再起動後も再現

## 結論

- 最終エラー: `ErrorCode::kDownloadOperationExecutionError (28)`
- 直接原因: 差分OTAの適用中、現行 `product` パーティションのソース読み出しで I/O エラーが発生し、ソースハッシュが取得できず（`found` が空）「Unrecoverable source hash mismatch」で中断
- 失敗箇所: `product` の extent `[481373, 512]`（512ブロック ≒ 256KB）で毎回同一。再現性が高い
- ダウンロードは 58% まで進行済みで、通信・空き容量・電池は要因ではない
- 進捗は常に 39% 地点から「再開（Resuming）」しており、過去の試行の状態を引き継いでいる

## 残る可能性（2つ）

1. **更新状態／スナップショットの破損**: 常に同じ試行を再開しているため、再開用の状態（仮想A/Bのスナップショット等）が壊れていると、実フラッシュが正常でも同じ箇所で落ち続ける
2. **フラッシュの読み出し異常**: その領域の物理的な読み出し不良。カーネルログは logcat に含まれないため未確認

## 最終判定（2026-11-18 12:32、3回目のログで確定）

更新状態のリセット（Google Play 開発者サービスのデータ消去＋再起動）後に実施した試行は、**Payload Attempt Number = 1 の完全な初回適用**で、0% から約10分かけて 4123/10669 operations まで実際に処理が進んだ。それでも **同一の product extent [481373, 512]、同一の SOURCE_COPY operation 4267、同一の期待ハッシュ、同一の ErrorCode 28** で失敗した。

よって結論は **2（その領域の読み出し異常）** とする。状態破損・ダウンロード・容量・通信・時刻は全て否定された。

### 決定

- **OTA での 14.0.26.0 化は断念する。** これ以上の再試行はしない
- **初期化（ファクトリーリセット）も行わない。** リセットで消えるのは /data であり、読み出しに失敗する product（読み取り専用のシステム側）は変わらないため、再挑戦しても同じ箇所で失敗する見込みが高い。紐付けや再設定の手間とリスクだけが残る
- **プロジェクトは V14.0.23.0 を土台に組み替える（プランB）**: blobs・カーネル prebuilt・SPL（2024-04-01）・fingerprint は全て実機の .23 に一致させる。turbo-boo の .26 前提の値は .23 用に読み替える
- アンロック後、書き込み前に当該領域の生読み出しテスト（リカバリ経由の dd と dmesg 確認）を行い、スナップショット層の問題か物理層かを最終確認する
- カスタムROMの書き込み（フルイメージ書き込み）は旧 product の読み出し検証を必要としないため継続可能。ただし書き込み後は、新しいイメージの読み戻しハッシュ検証を行ってから初回起動する（当該領域に書いたデータが保持できるかの確認を兼ねる）
- 自前ダンプ取得時は当該領域の読み出しエラーに備え、エラー耐性のある方法（noerror 等）を使う
