# 安全ルール（文鎮化防止）と復旧手順

最優先の3本柱の筆頭。方針は「壊れたら直す」ではなく「壊れる操作をできないようにする」。
Xiaomi 機は EDL 復旧に認証が必要な場合があり、最後の砦として当てにできないため、予防を全てとする。

## 前提（2026-11-18 調査で判明）

- **Xiaomi 公式の Fastboot ROM はこの機種には存在しない。** アップデートがキャリア（KDDI）配信のため、公式サーバーにフルROMが置かれていない。詳細は [research/stock-rom-findings.md](../research/stock-rom-findings.md)
- 有志製 Fastboot ROM はあるが（最新は V14.0.21.0）、製作者自身が「v14.0.4.0 以降はパーティションサイズ変更があり、文鎮化報告もあるため boot.img の使用のみ推奨」と警告している。無条件の復旧保険にはならない
- したがって復旧の本線は **焼く前に実機から取る自前フルダンプ** とする

## 絶対ルール

1. カスタムROMが入った状態でブートローダーを再ロックしない（文鎮化の最大原因）
2. 純正より古いファームウェアを焼かない（ロールバック防止＝ARB に引っかかると復旧困難。実機の anti 値は未確認）
3. 自前フルダンプがPC側にあり検証済むまでは、書き込みを伴う工程に進まない
4. 有志 Fastboot ROM をフル復旧に使うかどうかは、使える範囲の切り分けが済むまで決めない（当面は boot.img 限定の前提）
5. 焼く対象は iris（XIG02）用であることを毎回確認する。他機種用イメージは絶対に焼かない

## 焼く前の必須バックアップ（復旧の本線）

アンロック直後、何も焼く前に、現在正常に動いている 14.0.23.0 の状態をフルダンプする。一時起動したリカバリ経由などで、書き込まずに読み出す方法を使う。

- 全パーティション（super を含む）を対象とする。特に以下は必須:
  - persist
  - modemst1 / modemst2 / fsg（IMEI系。失うとROMを焼き直しても電波が直らない）
  - boot / dtbo / vbmeta / vbmeta_system
- ダンプはPC側に2か所コピーし、ファイルサイズとハッシュで検証する

ダンプが無い・検証できていない状態では次の工程に進まない。

## 手順の原則

- 最初のテストは書き込まない方法から: DSU、または `fastboot boot` による一時起動。ダメでも再起動で戻れる方法を優先する
- 書き込みは1工程ずつ。起動確認が取れてから次に進む
- flash は手打ちで連打せず、チェック付きスクリプトだけを使う

## フラッシュ前チェック（スクリプトで自動停止）

以下が1つでも合わなければスクリプトは止まること。

- `fastboot getvar product` が iris である
- 書き込む全ファイルが存在し、SHA256 がマニフェストと一致する
- 必須バックアップが存在する
- 端末の電池残量が十分にある（目安50%以上）
- 自前フルダンプがPC側にあり検証済みである

## 復旧手順（起動しなくなった場合）

1. Fastboot モードに入れるか確認する
2. 入れる場合: 焼く前に取った自前フルダンプを fastboot で書き戻す（これが本線）
   - 有志 Fastboot ROM のフル焼きは、切り分けが済んでいない段階では使わない
   - Mi Flash 系ツールを使う場合も **clean all and lock は絶対に選ばない**
3. IMEI系が壊れた疑いがある場合は、焼く前に取った modemst / fsg / persist のバックアップから戻す
4. Fastboot にも入れない場合は EDL が候補になるが、Xiaomi では認証が必要な場合があり確実ではない。ここに至る操作をしないことが前提

## 記録

- 焼いたビルド、ファイルのSHA256、結果（起動可否・確認項目）はその都度記録する
- 正常に動いたビルドには「known-good」として印を付け、いつでも戻れる基準点にする
